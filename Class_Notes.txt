		- Stages of DevOps :
		
			- Continuous Development :
				- It is the capability of the Development Team to Continuously Develop the Application Source Code.
				- It is used to Improve Developer's Productivity, by using intuitive Tools like Modern IDEs, GIT, DVC Pipelines
				
				
			- Continuous Integration :
				- It is the capability of the Development Team to Continuously Integrate the Changes for further testing.
				
				- Automated :
				
					- Build
					- Packaging 
					- Unit Testing					
					- Promote to Test Environment
					- Notify thru Email
				
			- Continuous Testing :
				- It is the capability of the Testing Team to Continuously Test the Changes.
				
					- Selenium
					
					- MLFlow 
					- Monitoring Services 
					
					
			- Continuous Delivery/Deployment :::
			
				- Continuous Delivery 
					- It is process to release the changes to production with manual approvals
					- This ia applicable for Monolith Application Architecture
					- Leads to Application Downtime during Production Releases.

				- Continuous Deployment
					- It is process to release the changes to production without any manual approvals
					- Can be achieved only with the Micro-Service Based Application Architecture
					- With this we can achieve Zero-Downtime during Production Releases.
					
					
				- Docker,Kubernetes,KubeFlow,GitHub-Actions

		- Misc. Git Cli Command 
		
			- Create Local Git Repository :
			
				- git init 			# To initialize Local Git Repository				
			
				- git add			# To Add the changes from Working Directory to Staging Area 

				- git commit 		# To Commit the Changes from Staging Area to Local Repository
				
				- git push 			# To Push the changes from Local Repository to Remote Repository
				
				- git clone 		# To Copy/Clone the Entire Remote Repository to Local Machine
				
				- git Fetch/Pull :::
		
					-> Both Git fetch and pull are used handle the incremental changes from remote repository.
					
					Git Fetch :
					
						- It is used to just check for the incremental changes from remote repository, if any incremental changes exist, it will update the details of the changes only in local repository. Git fetch will never Update the Working Directory.
						
						- Do explicit merge to update the Working Directory					
						
				
					git Pull :
					
						- It is used to check for the incremental changes from remote repository, if any incremental changes exist, it will update the details of the changes in local repository as well as in the Working Directory.	

						- Git Pull is used to Keep the Local Repository In-Sync with Remote Repository
						
						
						- git pull ==> git fetch + git merge 
		
		
				- Fork 				# Is used to Copy one Remote Repository to Another Remote Repository

				- git init 			# To initialize New Local Git Repository
									# Create .git Directory
									# Create a default branch - main/master Branch
